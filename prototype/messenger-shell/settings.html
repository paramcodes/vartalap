PROTOTYPE

ADR behind each choice

  • The handle is shown, not edited — read-only TEXT, not a disabled input. A greyed control reads as a promise the build has not kept yet; text does not. The handle is claimed once and never changes, because the auth library has no history table and a released handle silently re-points to a stranger.
  • The display casing IS editable. One name, two controls, different lifetimes. That contrast is the point of variant A.
  • Three homes, one rule — needed before first paint → device-local; needs server authority → account-scoped; scoped to a relationship → lives on the membership. Theme fails the first test, which is why it is local.
  • Disclosure changes broadcast over the socket; every privacy change is a POST only the author sees. Renaming yourself updates every conversation you are in, immediately.
  • Never render a disabled switch, render a sentence. A disabled switch is a promise the build has not kept. Variant C puts a sentence beside a real one so the difference is visible.
  • Read-receipt sharing is per-conversation, and the copy does not claim invisibility. Turning the marker off hides when you read, not how fast. Saying otherwise would be a lie.
  • No bio. A moderation surface, not a column cost. Its absence should read as deliberate, so it is named rather than simply missing.
  • The avatar goes through the same pipeline as an attachment — a derived variant only. The raw upload is never served.
